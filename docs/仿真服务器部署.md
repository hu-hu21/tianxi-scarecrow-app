# 公网仿真设备部署（47.94.214.62:1819）

`tools/demo_server.py` 是一台“假设备”：在公网服务器上模拟固件 v1.2.0 的全部接口，
并提供实时摄像头画面、视觉检测、小车路线和水阀联动，用来在没有硬件的情况下联调三个客户端。

- 单文件，只用 Python 标准库，不需要 pip 安装任何东西（Python 3.6+ 即可）。
- 默认监听 `0.0.0.0:1819`，可用 `--port` 改端口，用 `--advertise` 指定对外展示的地址。
- 所有数据在内存里，进程重启后恢复默认值。

## 1. 它模拟了什么

| 模块 | 行为 |
|---|---|
| 设备状态 | 电压、昼夜、静音时段、雷达脉冲、运行时长、驱赶状态机（IDLE / ACTIVE / COOLDOWN） |
| 参数配置 | 音量、灵敏度、冷却、音轨数、驱赶时长、静音时段、ADC 阈值、触发窗口 |
| 视觉 | 摄像头 MJPEG 实时流 + 单张快照；病虫害 3 个病斑、安全帽/反光衣检测；每 12 秒切换一次防护状态 |
| 小车 | 6 个默认航点，按 0.45 m/s 模拟行驶，支持启动/暂停/停止/回原点，电量缓慢下降 |
| 水阀 | 手动开阀定时关闭；自动规则按温湿度/降雨判断；降雨时强制关阀 |
| 天气 | 按服务器本地时间生成温度、湿度曲线，每小时有 5 分钟“降雨” |

画面和识别结果都是程序生成的，**不是真实 YOLO 推理**，用于验证界面、接口和交互流程。

## 2. 本机先跑一遍

```bash
python tools/demo_server.py --port 1819
```

浏览器打开 `http://127.0.0.1:1819/`，能看到状态面板和实时画面。
客户端地址填 `127.0.0.1:1819` 即可联调。

只生成一张画面（不改任何状态）：

```bash
python tools/demo_server.py --render frame.jpg
```

## 3. 部署到 47.94.214.62

### 3.1 上传文件

```bash
ssh root@47.94.214.62 "mkdir -p /opt/scarecrow"
scp tools/demo_server.py root@47.94.214.62:/opt/scarecrow/
```

没有命令行环境时，用宝塔面板 / WinSCP 把 `demo_server.py` 传到 `/opt/scarecrow/` 即可。

### 3.2 先在前台试运行

```bash
cd /opt/scarecrow
python3 demo_server.py --port 1819 --advertise 47.94.214.62:1819
```

看到下面几行就说明起来了：

```
稻草人仿真设备 v1.0.0
监听      http://0.0.0.0:1819
访问面板  http://47.94.214.62:1819/
客户端填  47.94.214.62:1819
```

### 3.3 放行端口（最容易漏的一步）

1. **阿里云安全组**：控制台 → 实例 → 安全组 → 配置规则 → 入方向 → 手动添加
   - 协议类型 `TCP`，端口范围 `1819/1819`，授权对象 `0.0.0.0/0`（演示）或你的固定出口 IP（更安全）。
2. **服务器系统防火墙**：
   ```bash
   # Ubuntu / Debian
   ufw allow 1819/tcp
   # CentOS / Alibaba Cloud Linux
   firewall-cmd --add-port=1819/tcp --permanent && firewall-cmd --reload
   ```

放行后在本机验证：

```bash
curl http://47.94.214.62:1819/healthz
curl http://47.94.214.62:1819/api/status
```

### 3.4 后台常驻

仓库里附带了 `tools/scarecrow-sim.service`，复制到服务器：

```bash
cp /opt/scarecrow/scarecrow-sim.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now scarecrow-sim
systemctl status scarecrow-sim
journalctl -u scarecrow-sim -f
```

`ExecStart` 里的路径和地址按实际情况改。不想用 systemd 时：

```bash
cd /opt/scarecrow
nohup python3 demo_server.py --port 1819 --advertise 47.94.214.62:1819 > sim.log 2>&1 &
```

## 4. 客户端怎么连

| 客户端 | 填哪里 | 填什么 |
|---|---|---|
| Windows | 【硬件设置】→ 服务器地址 | `47.94.214.62:1819` |
| Android | 【硬件设置】→ 服务器地址 | `47.94.214.62:1819` |
| iOS | 设置页「设备地址」 | `47.94.214.62:1819` |

服务器地址填服务端，设备地址可留空；留空时使用服务端的「当前设备」。
客户端会把服务器地址和设备地址一起保存，下次启动自动连接。

连接后，「扩展功能」里的摄像头地址、AI 服务地址会默认跟随设备地址；
如果单独填写，摄像头填 `http://47.94.214.62:1819/api/camera/stream`，
AI 服务填 `http://47.94.214.62:1819`。

主界面能看到「已连接」、电压约 12.4 V、状态在 IDLE / ACTIVE / COOLDOWN 之间变化，就说明通了。

### 独立转发通道

多个客户端同时连接同一个服务端时，服务端按请求头 `X-Client-Id` 为每个客户端
建立独立通道：通道首次解析到设备地址后自动固定，之后该客户端不带设备地址也会
继续走同一台设备，互不影响。没有 `X-Client-Id` 的旧客户端按来源 IP 区分。

- `GET /server/channels`：查看当前通道、绑定设备、请求数、流量和最后活跃时间
- `GET /server/health`：返回 `channels` 字段，等于当前通道数
- Windows 客户端与 Android 客户端均已在每个请求自动携带 `X-Client-Id`

例如：

```bash
curl http://47.94.214.62:1819/server/channels
```

## 6. 演示时能看到的细节

- 画面里有一名作业人员，每 12 秒在「戴安全帽 + 反光衣 → 未戴安全帽 → 未穿反光衣 → 正常」之间切换；
  切到违规状态时，防护服页面会出现红色报警框。
- 三处病斑固定在画面中部，病虫害页面会返回 3 个检测框和置信度。
- 雷达会随机触发驱赶，状态机自动经历 `ACTIVE`（约 8 秒）→ `COOLDOWN`（约 30 秒）→ `IDLE`。
- 自动灌溉默认“湿度低于 60% 且温度在 5~38℃ 且无降雨”时开阀；服务器时间 22:00–06:00 会标记为夜间。

## 7. 注意事项

- **没有鉴权**：接口和画面任何人都能访问，只适合演示。建议安全组只放行自己的 IP，演示结束就删掉 1819 规则或停掉服务。
- **明文 HTTP**：不要在这台服务器上放业务数据；Android 客户端已允许明文流量。
- **服务器时区**：昼夜、静音时段、天气曲线都用服务器本地时间，systemd 里已设置 `TZ=Asia/Shanghai`。
- **参数不落盘**：重启进程后配置、路线、水阀状态都会回到默认值。
- **CPU**：一个 MJPEG 客户端约占 5%~10% 单核（192×144、约 2.4 fps）；标注流 1 fps 更耗 CPU，演示时别同时开太多。
- **这是模拟器**：视觉结果是按画面里预先画好的目标生成的，不能用来验证真实模型精度；真实推理请用 `tools/yolo_service.py`。

## 8. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 浏览器打不开，curl 超时 | 安全组或系统防火墙没放行 1819；先在服务器上 `curl 127.0.0.1:1819/healthz` 确认服务在跑 |
| 提示 `Address already in use` | 端口被占用，换 `--port` 或停掉旧进程 |
| 客户端连不上，但浏览器能开 | 客户端地址没带端口；必须填 `47.94.214.62:1819` |
| 画面一直黑/不刷新 | 检查「摄像头地址」是否为 `http://47.94.214.62:1819/api/camera/stream`；公司网络是否拦截了长连接 |
| 识别一直 0 个目标 | 旧版客户端存在数组解析问题，更新到本次附带的 exe / apk |
| 手机提示明文流量被禁止 | 当前 APK 已开启 `usesCleartextTraffic`，请使用本次构建的版本 |
| 状态一直是 COOLDOWN | 冷却时间默认 30 秒，等一会儿会自动回 IDLE；也可以点「立即驱赶」 |
